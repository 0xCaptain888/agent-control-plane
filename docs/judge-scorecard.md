## The scoring sentence

> AgentGuard makes the Arbitrum Agent economy usable by giving a Treasury Agent a
> public marketplace, a bounded hiring decision, and an escrow that releases
> only when an independently signed result matches the task policy.

## What we do not claim

- No mainnet execution claim.
- No third-party formal audit claim.
- No invented user or revenue metrics.
- No claim that deterministic demo receipts are real trades.

## Highest-leverage remaining work

These are the only remaining upgrades expected to move the score materially:

1. **Record the final three-minute video.** Use the Arbitrum-specific URL, name
   the Buyer and Seller Agents, show the decision trace, then VERIFIED → BLOCKED
   → FROZEN and one real transaction page. Do not mix the BNB edition into this
   video.
2. **Collect three independent user records.** Each participant should complete
   one bounded test, provide a consent/reviewer note, and link the task receipt.
   Builder-controlled runs or multiple accounts owned by the builder do not
   count as external traction.
3. **If time permits, create one real chain-backed Buyer/Seller task.** The
   current Buyer → Seller path is a deterministic, reproducible control-plane
   demonstration; the separate BNB and Arbitrum transactions are real testnet
   settlement anchors. A fresh task whose metadata names both Agents would make
   the product story even harder to dismiss, but it is not required for the
   existing contract proof.

Everything else — more Agent categories, mainnet deployment, production auth,
or a new frontend — is lower value before submission and increases demo risk.
